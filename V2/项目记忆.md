# V2 项目记忆

## v0.12

- 用户需求：先看一版“UI 友好、方便人类操作”的 V2 前端网页面板。
- 已实现：`V2/web_panel.py` 内置单文件前端页面 + 本地 HTTP API，直接调用 `run_v2_first_feature()`，无需改动主流程入口。
- 首版能力：模式切换、手动菜名输入、温度/质量/数量调参、一键运行、结果与图片预览、最近输出历史。

## v0.11

- 用户要求：以后无需手动点 Review/Commit，V2 流程由 AI 自动同步仓库。
- 已落地：规范中新增“默认自动执行 `git status -> commit -> push`”的硬规则，并保留“用户明确禁止或远端阻塞”例外。

## v0.10

- 用户问题确认：V2 自动造菜缺少历史创意记忆与参考菜追溯，导致近期结果口味方向重复（如连续“蒜香”）。
- 已修复：V2 自动造菜直接复用 V1 核心函数，启用 V1 同款反重复策略与历史禁用约束。
- 已落地：新增 `V2/dish_idea_memory.jsonl`，并在日志中打印参考传统菜和记忆文件路径，方便排查“由哪道传统菜衍生而来”。

## v0.09

- 新要求确认：只有含 `{变量}` 的位置可以改写；未含变量的模板行必须保持 100% 原文。
- 已落地：豆包不再输出整段 prompt，而是仅输出变量替换数组；程序负责把替换值填回原模板。
- 结果：模板固定文本（尤其 `文案` 行）不会被模型改写，避免调试过的 prompt 被意外污染。

## v0.08

- 补充修正：v0.07 的重排虽然生效，但在少数单段输出里会把“真实拍摄”误判为“拍摄分类”起点，导致分段错位。
- 已修复：分类关键词匹配增加中文标点/空白边界约束，仅在更像“新字段起始”的位置触发。
- 同步增强：豆包提示词生成阶段新增“11 分类标签 + 空段”硬约束，优先从源头保障可读结构。

## v0.07

- 用户诉求：提示词文件需要像 `cankao.txt` 一样按分类分段，便于人类阅读和后续优化。
- 已实现：新增 `format_prompt_by_template_sections()`，先按模板抽取分类标签，再从模型输出中回填对应内容，最终按“分类 + 空行”格式落盘。
- 兼容性：支持模型返回单行长句、半结构化文本和模板化文本三类输出形态。

## v0.06

- 用户困惑点：`AUTO_GENERATE_DISH_IDEA=1` 时怀疑未自动造菜，以及“已有图片但终端出现失败信息”。
- 诊断结论：`20260601_031028_main_32364.log` 已确认该轮实际是自动造菜并成功生图；此前失败信息来自旧目录旧轮次，且 V2 存在多段重试分支容易造成感知混乱。
- 已修复：输出日志增加“开关值/命令行模式/最终模式”；生图流程改为更接近 V1 的单路径逻辑，仅保留超时重试。

## v0.05

- 新增根因：`V2/config.env` 中 `OPENAI_BASE_URL=` 空值会把环境变量设置为空字符串，OpenAI SDK 读取后会报 `UnsupportedProtocol`（上层表现为 `Connection error`）。
- 已修复：V2 生图客户端在空值场景强制使用官方默认 `https://api.openai.com/v1`。

## v0.04

- 进一步定位：同机直测 `OpenAI(api_key, timeout)` + `gpt-image-2` 能成功返回图片，排除 key 错误与官方网络不通。
- 根因收敛：V2 先前为生图客户端注入自定义 `httpx.Client`，与 V1 行为不一致，导致在当前环境下偶发/持续 `Connection error`。
- 已修复：V2 生图客户端改回 V1 同款初始化，仅保留 `api_key/timeout`（和可选 `base_url`）。

## v0.03

- 排查结果：`OPENAI_API_KEY` 读取变量名与 V1 一致，均为 `OPENAI_API_KEY`，并来自根目录 `.env`。
- 关键差异：V2 先前显式 `HTTP_TRUST_ENV=0`，导致不继承系统网络环境；在当前机器上该模式访问官方 OpenAI 会超时。
- 已修复：默认改为 `HTTP_TRUST_ENV=1` 并同步配置文件，现与 V1 的网络行为一致。

## v0.02

- 问题复盘：当豆包改写失败走本地降级模板时，旧正则仅匹配 `{变量}` 与 `{变量：...}`，未覆盖 `{变量，...}`，导致个别行残留占位符。
- 已修复：统一占位符规则为 `TEMPLATE_PLACEHOLDER_PATTERN`，降级替换和结果校验共用同一规则，避免再次漏替换。
- 结果：`cankao.txt` 中含中文逗号注释的变量位也能被按最新菜名语义替换。

## v0.01

- 目标：把 V2 做成与根目录主流程并行的独立版本，先实现首个功能闭环。
- 已实现：`AUTO_GENERATE_DISH_IDEA` 控制自动造菜或手动菜名读取。
- 已实现：读取 `cankao.txt` 后由豆包补全 `{变量}` 并生成最终提示词 txt。
- 已实现：把最终提示词直接投喂 `gpt-image-2` 生图，输出到 `V2/output/时间戳_菜名`。
- 默认配置：`OPENAI_IMAGE_QUALITY=low`，`OPENAI_IMAGE_COUNT=1`。
