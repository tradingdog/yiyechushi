# V2 项目规范

## 当前版本

v1.77

## 运行日志

1. 造菜/指定/补生/生菜：任务结束写入菜品或批次目录下的 `_run_log.txt`，并更新 `_run_meta.json`（含 `run_params`、`image_generation_settings`）。
2. 平台发布：写入 `_publish_log.txt`（含部分失败与中断场景）。
3. 细节图生图必须同时上传海报参考图与 `cankao/juese.png`；日志中应能查到 `细节图生图参考图` 与 `参考图生图输入` 两行。
3.1 细节图前气泡文案：全库 `*_气泡文案.txt` 汇总至 `V2/bubble_copy_history.txt` 后投喂豆包，禁止与历史重复；日志见 `气泡文案历史已同步`。
3.2 平台文案：话题须为各平台真实热门短标签（2～8 字常见），禁止自造长尾；标题禁止写完整菜名（封面已有菜名），须点出核心食材/主料并按平台写高转化钩子（公众号强点击+标点，抖音/快手悬念促展开）；本地校验话题长度与自造词、标题禁完整菜名且含主料。
3.3 文案禁用套话：`V2/cankao/huasu.txt` 仍用于气泡文案等路径；平台发布文案不再注入 huasu 词库或本地套话校验。
3.5 生图中断续跑：选中仅有造菜信息/生图失败记录的菜品，点面板 **继续生图**（或切「补生」手动勾选）；在原目录补海报/细节/菜谱/封面/文案/PS，勿重新「指定」整道菜。
4. 生图失败重试：`_run_log.txt` 应可见 `第 x/3 次`、`本轮 n=`、`已累计 a/b`、`补生剩余` 等行；张数不足时保留已返图片并减量补生；`IMAGE_REQUEST_RETRY_COUNT` 默认 3（总尝试次数）。

## Photoshop 合成

1. 只对 **publish 里当前入选的四张源图**（海报 / 细节 / 菜谱 / 封面）做 PSD 合成，不得扫描整个 `publish/` 目录批量处理。
2. 补生某一类图时，默认 **只合成刚生成/变更的那一类**；其它已在 `publish/final` 且源图未变的，跳过不再进 Photoshop。
3. 判断「已合成」：`publish/final` 中对应 01–04 槽位文件存在，且其修改时间不早于 publish 源图。
4. 单独勾选「PS 合成」且未补生图片时，仅补齐 **尚未合成或源图已更新** 的槽位。
5. 合成前若检测到 Photoshop 已运行，程序自动关闭后继续，不再要求用户手动关。

## 菜品池

1. 点击「移出」不做确认，整目录移动到 `V2/dish_archive/`（保留 `dish_pool/` 或 `output/` 相对路径），可从备用目录手动恢复。
2. 收藏状态写入 `V2/dish_favorites.json`；默认排序为收藏优先。
3. 自动/手动造菜新建目录成功后，按菜名去重：同名旧目录（含 dish_pool 生菜仅文案项）自动归档，菜品池只保留最新一条。

## 前端面板

1. 看图栏「非发布图」下选中候选海报，点 **设为海报并补生**：原 `publish/` 与 `publish/final/` 移入同菜品 `history/{timestamp}/` 存档，再以该图补生细节/菜谱/封面并 PS 合成至 `publish/final/`；细节/菜谱/封面数量与画质沿用造菜栏「参数调节」。
2. 看图栏「非发布图」点 **替换** 进入多选模式，选中海报/细节/菜谱/封面候选后点 **执行替换**：复制到 `publish/`、PS 合成并更新 `publish/final/` 对应槽位（不存档、不重新生图）；同类型只能选一张。
2. 锚点图须为菜品目录内、`publish/` 与 `history/` 外的候选图（通常为根目录未入选海报）。
3. `web_panel.py` 在进程启动时会把整页 HTML 载入内存，**不会热更新**。
4. 只要修改了 `web_panel.py` 或面板相关逻辑，任务结束前必须重启前端：先结束占用 `8765` 端口的旧进程，再执行 `python V2/web_panel.py`。
5. 公网访问：双击根目录 `start_v2_public_panel.bat`，通过 Cloudflare 免费隧道暴露 `8765`（无用户名密码）；公网地址写入 `V2/public_tunnel_url.txt`，停止用 `stop_v2_public_panel.bat`。每次重启公网地址会变。
6. 自定义生图：面板最右栏；图片保存在 `V2/custom_image_gen/images/`，历史元数据 `V2/custom_image_gen/history.json`；生图渠道与顶栏「官方 GPT / 丝路」一致。
7. 顶栏生图：默认 **官方 GPT**（`.env` 的 `OPENAIOFFICIAL_API_KEY`）；可选丝路。支持画质、比例、1K/2K/4K 档位；PSD 模板按 `template_{宽}x高}.psd` 自动匹配（见 `tools/photoshop_template/README.md`）。
8. 提示用户用 **Ctrl+F5** 强刷浏览器，避免缓存旧页面。
9. 完全重启面板：双击仓库根目录 `restart_v2_web_panel.bat`（结束 8765 端口旧进程后重新启动）。
10. **每次 V2 版本号递增**（不论是否改面板 UI），必须同步 `V2/web_panel.py` 的 `PANEL_VERSION` 与 `项目规范.md`「当前版本」一致；改完后重启面板，左上角版本号才与代码一致。

## 版本规则

1. 只要本目录发生新增、修改、删除，就视为一次版本变更。
2. 版本号从 v0.01 开始，每次变更递增 0.01，例如 v0.02、v0.03。
3. 每次版本变更后，必须同步更新 `版本记录.md` 和 `项目记忆.md`。
4. 若存在代码或文档变更，优先先完成版本更新，再进行 git 提交与推送。
5. 任何一次任务只要产生代码、脚本、配置或文档改动，在结束前都必须完成 git status 检查、版本更新、本地提交与推送 GitHub；除非用户明确要求不推送，或远端出现客观阻塞。

## Git 与 GitHub 规则

1. 提交标题格式固定为：v版本号：中文说明。
2. 所有提交说明、变更说明、版本记录，主要使用中文。
3. 只要有目录改动，默认流程为：更新版本号 -> 更新文档 -> git 提交 -> 推送 GitHub。
4. 若远程仓库或 GitHub 登录未完成，先完成本地提交，并在 `项目记忆.md` 记录阻塞原因。
5. 若本地存在未提交改动，不得直接结束任务；必须先明确这些改动是否纳入当前版本，并完成提交与推送或记录阻塞原因。
6. 从 v0.11 起，V2 任务默认由 AI 自动执行 `git status 检查 -> 本地提交 -> 推送 GitHub`，不再要求用户手动点击 Review 或 Commit；仅在用户明确要求不提交/不推送，或远端客观阻塞时可中止，并必须在 `项目记忆.md` 记录原因。

## 语言规则

1. 说明文档、注释、输出信息优先使用中文。
2. 遇到必须使用英文的技术字段、库名、接口名，再保留英文。
